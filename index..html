CatFinder

Fullstack-plattform för bortsprungna katter

Webbapplikationer · grupprojekt · VG

Min roll: Jag arbetade i både backend och frontend – från API-lagret och databasen till React-gränssnittet.

En publik tjänst där kattägare lägger upp efterlysningar och allmänheten rapporterar upphittade katter. Backend är ett ASP.NET Core-API byggt enligt Clean Architecture i fem separata lager – API, Application, Domain, Infrastructure och Test. Application-lagret använder CQRS via MediatR, validering med FluentValidation och mappning med AutoMapper. Autentisering sker med JWT och BCrypt-hashade lösenord, med rollstyrd åtkomst och en separat adminportal för moderering av annonser och anmälningar. Datalagret körs på EF Core mot både SQL Server och PostgreSQL, med health checks och e-postutskick via Resend. Samtliga controllers täcks av enhetstester skrivna i NUnit med Moq. Frontend är byggd i React med Vite, TanStack Query för datahämtning och cachning, Zustand för state och skyddade rutter för både inloggade användare och administratörer. En av funktionerna genererar utskrivbara efterlysningsaffischer som PDF med QR-kod direkt i webbläsaren.

CleanArchitecture API

Enskild inlämning i webbapplikationer

Webbapplikationer · enskilt · VG

Ett REST-API byggt från grunden enligt Clean Architecture med fyra tydligt separerade lager. Domain-lagret innehåller entiteter och repository-interface utan beroenden utåt. Application-lagret hanterar affärslogiken genom CQRS – varje operation är ett eget kommando eller en query med tillhörande handler via MediatR – tillsammans med DTO:er och AutoMapper-profiler. Infrastructure-lagret implementerar repositories mot EF Core och SQL Server, och API-lagret exponerar controllers för produkter, användare och autentisering med JWT Bearer. API-dokumentationen genereras med Scalar.

SmartHomeHub

Designmönster i praktiken

Objektorienterad design · VG

Ett smart hem-system i C# där poängen inte är gränssnittet utan hur koden är strukturerad bakom kulisserna. Projektet implementerar fyra designmönster från Gang of Four: Observer, där dashboard, loggning och revision prenumererar på systemhändelser; Command, där varje åtgärd kapslas in som ett objekt och körs via en invoker; Strategy, med utbytbara driftlägen för normal-, eco- och partyläge; samt Facade, som ger ett förenklat gränssnitt mot undersystemen. UML-dokumentation ingår i repot.

Mini E-commerce

Från problem till krav, UML och prototyp

Objektorienterad analys · VG

Ett analysprojekt som visar hela kedjan innan en rad produktionskod skrivs. Utgår från ett konkret problem – små onlinebutiker behöver något enklare än de stora e-handelssystemen – och arbetar sig fram genom intressentanalys, funktionella och icke-funktionella krav, MoSCoW-prioritering och use cases. Analysen dokumenteras i UML med både klassdiagram och sekvensdiagram. Avslutas med en fungerande prototyp i semantisk HTML, CSS och JavaScript – produktlista, produktdetaljer och kundvagn med räknare som sparas i LocalStorage – byggd helt utan externa bibliotek för att visa att strukturen håller på egen hand.
